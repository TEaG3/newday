What changed, version by version.

Newest first. Called ORBIT until v1.1. Each version's zip and checksums are on its release page.

1.3

2026-11-19 · download

Themes: twelve looks for the launcher, a selector in the setup panel, and themes anybody can make.

New

  • Twelve themes. Torres (the new default: prisms of light in a blue night), NULD (v1.2's look), Cristal, Aurora, Liquid, Onda, Orbit, Techstep, Wireframe, Neuro, Fósforo and Papel. Each has its own colours, animated background, loading screen, launch screen and way of marking the selected game. The layout is the same in all of them.
  • Theme selector. START, then Theme: each theme is shown at once behind the panel. Saved as [ui] tema in config.ini. To keep v1.2's look, pick NULD.
  • Themes from folders. A folder in nuld/themes/ with a theme.ini (a name, a built-in theme as its base and eleven colours) and, optionally, a 1280 x 720 fondo.jpg is a theme of its own. The guide is in the manual and in docs/themes.md.
  • Theme maker. A page that builds that folder in the browser, with a live preview of the home screen, and downloads it as a zip.
  • Saving the setup no longer restarts NULD. Language, theme, memory card and video apply at once; it only starts again when the game sources or the network changed.
  • A loading sound for the new themes: air rising and a low piano strike in a hall. NULD keeps its own.

Fixed

  • After changing the language in the setup panel, the disc's title on the home screen stayed in the old language.

Known issues

  • Only Torres and NULD have been timed on a console (60 frames per second on a SCPH-75001). The other ten ran on the same console without visible stutter, but were not timed.
1.2.14

2026-11-17 · download

Covers from your home server, the interface in Portuguese, and the PlayStation 2 logo before the games.

New

  • Covers from the home server (#19). The catalog serves the server's ART/ folder, with OPL's names (ART/SLUS_209.46_COV.png or .jpg for games, ART/<ELF file>_COV.png for apps). The launcher asks the server for the cover of each of its games and apps before downloading one from the internet. Needs the server's nuld_catalog.py from this zip's server/; restart it with systemctl --user restart nuld-catalog.
  • Portuguese interface. In config.ini set [ui] idioma = pt; the setup wizard of a new drive offers it too. The in-game menu and the achievement notices are in Portuguese as well.
  • PlayStation 2 logo before the games. In config.ini set [juegos] logo = si and each game starts with the PlayStation 2 logo, as from a disc. Off by default. A game from another region than the console (PAL on an NTSC console or the reverse) may not start this way: leave it off for those. Not tested on a console yet.
1.2.13

2026-11-15 · download

Apps from your home server, OPL's ART folder, and square covers for PS1 games and apps.

New

  • Apps from the home server. The catalog now also lists the server's APPS/ folder, in OPL's layout (a loose .elf, or a folder with title.cfg holding title= and boot=). Pressing X downloads the ELF to nuld/red.elf on the USB and runs it. Only the ELF is downloaded: an app that reads other files from its own folder still has to be on the USB. Needs the server's nuld_catalog.py from this zip's server/; restart it with systemctl --user restart nuld-catalog.
  • OPL's ART folder (#16). Covers are read straight from ART/, with OPL's names: ART/SLUS_209.46_COV.jpg or .png for games, ART/<ELF file>_COV.png for apps (for example ART/OPNPS2LD.ELF_COV.png). The launcher looks in the ART/ folder of its own drive and of the game's drive. It converts each image once into covers/, and does not download a cover for that game from the internet. Transparent PNGs are drawn over NULD's background.
  • Square covers for PS1 games and apps (#27). PS1 covers are no longer squashed into the DVD case shape: they are drawn square, like a CD case, and so are app covers. PS1 covers downloaded by earlier versions are downloaded again in the new shape. tools/covers.py --square makes square covers by hand; app covers made earlier with covers.py have to be made again with --square.
  • Games on a udpfs server reconnect after a lost link. Before, once udpfs gave up on the server, every later read failed and the game crashed at its next load. Now it finds the server again (for up to about a minute) and retries the read. Not tested on a console yet.
1.2.12

2026-11-08 · download

The splash counts the games on your home server.

Fixed

  • The splash stopped at "00 / 01" with games on a home server: its total counted only what is on the USB, and the server's games were never added. They are now counted as the catalog arrives (and HD Loader games too). The line now reads "Cargando juegos" / "Loading games": it is the game list, covers load later as they show.
1.2.11

2026-11-08 · download

Fixes a black screen after the splash.

Fixed

  • Black screen after the splash, at every boot. The update check waits for GitHub over HTTPS; when a server went quiet the launcher waited forever (the network library here ignores the 15-second limit the code asked for), and the screen stayed black. HTTPS reads now give up after 8 seconds of silence, and launcher.txt says where the check stopped. If you are stuck on v1.2.8: on the USB, in nuld/config.ini, set [actualizaciones] buscar = no to boot, update by hand, then set it back.

New since v1.2.5

  • Save icons for the games on your home server (needs the server's nuld_catalog.py and nuld_hash from this zip's server/; restart it with systemctl --user restart nuld-catalog).
  • Covers for apps: covers/<title>.c16 and _s.c16, named after the title the launcher shows.
  • Faster covers and achievements: covers read in one request per file; the first achievements query no longer waits for the update check; the client's "still loading" answer is asked again 5 times a second.

Changed

  • launcher.txt logs each request for a home-server game's memory card ("nuld vmc remote"), to find why its save icon does not show yet.

2026-11-07 · download

Achievement unlocks show up in the game.

New

  • Unlock notice in the game. When the achievements client announces an unlock, the game pauses for about 2.5 seconds under a box with "LOGRO DESBLOQUEADO 5 PTS" (or "ACHIEVEMENT UNLOCKED") and the achievement's title. The titles come from the client's list at launch (the ones still to earn, up to 128 per game).

Fixed

  • The in-game menu did not show during gameplay (Tekken 5 in a fight: the game froze for 10 s, no box). The menu, and now the notice, wait for a moment when the game is not sending anything to the GS (up to 2 s).
  • The achievements list (○) of games with subsets stayed empty ("could not read the list"): Tekken 5's answer names the subset's achievement count first.

Fixed

1.2.3

2026-11-07 · download

Achievements inside games, for real this time, and a lighter agent.

Fixed

  • In-game achievements never unlocked since v1.1. The launcher handed Neutrino the agent's config file instead of the game's watch list, so the console never sent the game's memory to the achievements client. The list of achievements on ○ was not affected.
  • Games froze at scene loads with achievements on (Tekken 5 from the home server). The agent kept about 25 KB of the IOP's 2 MB for snapshots it never sends; it now keeps 4 KB, one packet's worth.
1.2.2

2026-11-07 · download

Achievements work again.

Fixed

  • No achievements unlocked in v1.2.1. v1.2.1's freeze fix checked the wrong DMA channel (SIF0, which is always running), so the console never sent the game's memory to the achievements client. It now checks SIF1, the channel it shares with the game.
1.2.1

2026-11-07 · download

Fix for a freeze with achievements on.

Fixed

  • Games froze at scene loads with achievements on (seen in Tekken 5 from the home server: black or frozen picture after a fight or a Story mode replay). The achievements telemetry sent its snapshot to the IOP in the middle of the game's own transfers; it now waits for a free frame. It also stops when the game reboots the IOP, until the agent says where its new buffer is.

ORBIT is now NULD: a new name, a new look, and nothing to redo on your USB drive.

Website, screenshots, manual: https://danielnuld.github.io/nuld/

New

  • A new name. ORBIT clashed with other PS2 projects; the launcher, its repository and its site are now NULD.
  • A new look. Black, steel and one acid accent: a loading screen with the four NULD logos taking turns over a wire sphere, 1 px frames and HUD corners on the selection, and the Archivo, IBM Plex Mono and Michroma typefaces. The in-game menu follows the same palette.
  • A new website with the loading screen running in the browser, every screenshot in a full-size viewer, and the setup guide as a manual of its own.

  • Loading over udpfs needs a wired network on both ends.
1.1

2026-10-12 · download

Setup without a PC, updates without a PC, and CRT TVs.

Website, screenshots, setup guide: https://danielnuld.github.io/ps2-launcher/

New

  • Setup wizard (#15). It opens by itself on the first boot, and with START any time after. In one screen: language, game sources (checkboxes), memory card mode, video, network, and installing ORBIT on a memory card with FreeMcBoot 1.966 set to start it (autoboot, a button, or an item in FMCB's menu). FMCB's other settings stay as they were, and its original config is kept as FREEMCB.CNF.bak.
  • ORBIT updates itself (#15). With the network cable in, ORBIT checks for a newer release at boot; START opens the update. Every file is checked against a manifest signed with the release key before anything is replaced, and the old files are kept as .old. Turn it off with [actualizaciones] buscar = no.
  • CRT TVs: the menu was 720p only, which a CRT shows as a black screen. Press L2+R2 together (it works blind) to switch the menu to 480i (576i on PAL consoles) and back; it is saved as [video] pantalla in config.ini. In 480i the games default to their native video mode too.
  • Run ORBIT from an MMCE SD card, no USB drive needed (#8). Settings, covers, apps and Neutrino live on the SD card; a USB drive becomes an optional extra game source.
  • udpfs without ORBIT's catalog (#10): with [juegos] servidor empty, any udpfs server (Server2PS2...) works, and its DVD/CD folders are listed like any other source.
  • SELECT shows every game source's status (#4): how many games each one found, or why it failed.

Fixed

  • The in-game menu ignored the controller on an 8BitDo adapter (#11): it read only one of the two copies of the pad data that the driver writes in turn.

Known issues

  • "Native" video mode can give a black screen on some HDTV setups: there, keep the default 480p.
  • Loading over udpfs needs a wired network on both ends; Neutrino's UDP transport does not recover from WiFi packet loss.

2026-10-05 · download

Fixes for what people found in v1.0. Thanks to everyone who opened an issue!

Website, screenshots, setup guide: https://danielnuld.github.io/ps2-launcher/

Fixed

  • USB games didn't boot on a real PS2 (#12). The in-game menu now draws over the game without saving what's under it (the game's next frame redraws it), which frees the memory that broke the boot. The menu still works on every source, in Spanish or English.
  • 128 game limit (#3). Now 1024. Covers are loaded only while they're on screen, and each view reads just the size it draws; the grid keeps a small thumbnail per game on the USB (covers/<serial>_h.c16, made the first time).
  • Covers: "No DNS" (#7). [red] dns now works with DHCP too, and if the router gives no DNS server ORBIT uses 1.1.1.1. The first download retries once if the connection fails right after the network comes up.
  • MemCard PRO 2 / SD2PSX didn't switch cards (#2). ORBIT now sends the game ID on every launch, whatever the game's source, as NHDDL does. To save on the card instead of the USB's virtual one, set the game's memory card to fisica (△, or [memorycard] modo = fisica for every game).
  • xeRAbora version (#5). The docs point to the client release ORBIT is tested with: v0.1.0-alpha.9.

Also

  • tools/covers.py is in the zip: it turns PNG/JPG files named by serial (SLUS-21376.png) into covers for mass0:/covers/ (python3 covers.py IN_DIR OUT_DIR, needs numpy and Pillow).
  • mass0:/launcher.txt now says why a game source or the network did not come up, and why a cover download failed.

Known issues

  • The in-game menu doesn't react to a DualSense on an 8BitDo adapter; a wired controller works (#11).
  • "Native" video mode can give a black screen on some setups: keep the default 480p.
  • Loading over udpfs needs a wired network on both ends; Neutrino's UDP transport does not recover from WiFi packet loss.
1.0

2026-10-04 · download

ORBIT's first public release: a game launcher for a real PlayStation 2.

Website, screenshots, setup guide: https://danielnuld.github.io/ps2-launcher/

What's in it

  • Three views (carousel, grid, list) at 60 fps, filters All / PS2 / PS1 / Apps, animated splash.
  • Covers downloaded by the PS2 over HTTPS (xlenore/ps2-covers), decoded and saved on the console.
  • 3D save icons of each game's newest save, read from the memory card.
  • Virtual memory cards per game or shared, created on first play; or the physical card, per game.
  • Per-game options (△): 480p / 1080i, compatibility modes, memory card.
  • In-game menu (L1+L2+R1+R2+START+SELECT): restart into ORBIT or power off; direct combos too.
  • RetroAchievements on real hardware: rcheevos-compatible game hash, ○ lists the achievements with your progress, and an agent inside the game feeds the xeRAbora client.
  • Home game server: udpfs + ORBIT's catalog service; server games keep covers, achievements and save icons.
  • Sources: USB, internal HDD (exFAT, HD Loader), MX4SIO, iLink, MMCE, UDPBD, udpfs; discs, PS1 (POPStarter), homebrew from APPS/.
  • Spanish or English ([ui] idioma), including the in-game menu and config.ini's comments.

Known issues

  • "Native" video mode can give a black screen on some setups: keep the default 480p.
  • Loading over udpfs needs a wired network on both ends; Neutrino's UDP transport does not recover from WiFi packet loss.
  • Achievement unlocks depend on the xeRAbora client being reachable on the same network.
